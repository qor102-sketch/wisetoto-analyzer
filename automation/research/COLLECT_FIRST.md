# 30분 전 수집 우선 운영 규칙

목표: Betman에 나오는 축구·농구·야구·배구의 일정을 최대한 누락 없이 등록하고, 시작 전 실제 자료와 종료 후 확인 결과를 분리 보존합니다. 기존 frozen PRE는 변경하지 않습니다.

## 데이터 흐름

1. DISCOVERY: 향후 7일 일정과 최근 14일 안에 보이는 경기 목록을 먼저 등록합니다. 30분 전이 아닌 일정 등록은 PRE 분석으로 계산하지 않습니다.
2. PRE-CAPTURE: 실제 경기 시작 30분 이내 ~ 킥오프 이전에만 배당을 저장합니다. 제공처가 최초로 반환한 시각을 pregameCapturedAt으로 보존하고 재조회로 바꾸지 않습니다. 배당이 없어도 경기와 수집 이력은 남깁니다.
3. MISSED-WINDOW/RESULT-ONLY: 일정 실행 지연 등으로 30분 창을 놓쳤거나 종료 후 처음 발견된 경기는 pregameCapturedAt=null로 남깁니다. 사후 배당을 과거 PRE로 위장하지 않습니다.
4. POSTMATCH: 경기 시작 2시간 뒤부터 14일 이내 범위에서 확인합니다. SportsAPI는 공식 종료 상태와 종목별 점수 정합성이 필요합니다. 거절·429·조회 오류 시 Naver의 별도 경기식별 결과를 시도하고, 확인이 안 되면 PENDING과 실패 사유를 보관합니다.
5. TRAINING READY: 실제 경기 전 수집 자료가 있고 독립적으로 최종 결과까지 검증된 경기만 40표본 운영 기준에 포함합니다. **40건을 채워도 무거운 PRE는 자동 재개하지 않습니다.** 종목별·리그별 표본과 시간순 백테스트를 별도로 검토한 뒤 운영자가 GitHub Repository Variable `WISETOTO_PREDICTION_RESTART_APPROVED=true`를 설정해야 신규 예측이 허용됩니다. 기존 저장 PRE의 종료 검증은 이 조건과 독립적으로 계속 실행합니다.

## 저장 경로

- automation-data/collect-first-state.json.gz: 최근 120일 활성 압축 장부. 더 오래된 기록은 월별·해시 버킷 `collect-archive/YYYY-MM-b.json.gz`에 먼저 저장합니다. 4,000건을 조용히 잘라내던 제한은 제거했습니다.
- automation-data/collect-first-public.json: 최신 150경기, 활성 장부와 누적 아카이브를 포함한 전체 건수의 읽기 전용 공개 자료.
- /api/automation/collection 및 /automation 화면: 경기 목록 등록 / 30분 전 수집 / 결과 검증 / 결과만 추적 / 누락된 외부 ID 등 구분. 배당이 처음 없었으면 나중에 최초로 확인한 실제 배당 시각을 `firstOddsAt`으로 보존합니다. 직전 정상 스캔의 배당 부족/식별 불가/수집 창 경과 건수도 구분 표시합니다.

## 주의사항

- GitHub Actions 약 10분 간격은 best-effort이며 실행 지연, Betman 오류 및 미등록 경기까지 100% 발견을 보장할 수 없습니다.
- 30분 전에 수집하지 못했어도 경기/결과만 저장은 가능하지만 해당 경기는 새로운 예측의 학습 표본에 포함하지 않습니다.
- 종료가 확인되지 않거나 점수 제공처가 없는 경기는 검증 완료로 위장하지 않습니다.
- 신규 실제 수집 및 데이터 공개는 Production 적용 승인 후 시작됩니다. PR 단위 테스트의 합성 경기 데이터는 실제 장부에 절대 삽입하지 않습니다.

## 장부 복구 안전장치

- GitHub API 장애(HTTP 429/5xx), 잘못된 압축/스키마, `automation-data` 분기 조회 불가 시 수집·게시 단계를 실패로 처리합니다. 빈 장부를 정상 초기 상태로 간주해 기존 기록을 덮어쓰지 않습니다.
- 실제 최초 실행임이 확인되는 경우(장부 404이고 `automation-data` 브랜치는 존재)만 새 장부를 초기화합니다.
- GitHub Actions가 PR에서 실행하는 자동 테스트는 저장소를 실제로 게시하지 않습니다. 새 장부의 실전 누적·공개 일치 여부는 배포 승인 후 별도 확인이 필요합니다.

## 영구 기록·공개 데이터 복구

- 기존 39건 공개/41건 원본 차이는 원본 손실이 아니라 41건짜리 `public-history.json`을 Actions가 생성한 뒤 Chromium 검증 실패로 `automation-data` 공개 단계가 건너뛴 문제였습니다.
- 이제 Chromium 실패와 무관하게 복원된 Tracker에서 공개 투영을 생성합니다. 이미 공개된 ID가 사라지는 PUT는 실패시키며, 식별/시각 필드가 불완전해도 원본을 누락하지 않고 공개 검토 대상으로 남깁니다.
- 오래된 수집 원본과 연구 배당은 각각 `collect-archive`, `research-archive`에 월별·해시 압축 파일로 먼저 보관한 뒤 활성 장부를 정리합니다. 원격 저장 오류·압축/스키마 충돌 시 삭제하지 않습니다.
- 향후 백테스트에서는 오래된 `research-archive`를 별도 오프라인 연구 입력으로 사용할 수 있습니다. 실시간 연구 모델은 최근 최대 365일/2,000 경기 표본을 기준으로 평가하며, 원본의 장기 보관과 학습 범위는 구분합니다.

## 배구 결과 검증 및 TOP1 게이트

- 국내 V리그는 Betman 외부 ID가 없어도 별도 네이버 경기 일정 조회를 시도합니다. 홈·원정팀·경기 날짜, 고유 경기 ID, 시작 시각(제공된 경우), 공식 종료 상태 및 3세트 선취 점수가 모두 일치해야 VERIFIED가 됩니다.
- 일정 소스 HTTP429/오류, 해외 리그, 중복된 팀 매칭, 종목 규칙에 어긋나는 점수는 PENDING 및 오류 사유로 남깁니다. 네이버 배구 실전 제공 범위와 안정성은 Preview/운영에서 추가 확인이 필요합니다.
- 새 연구 TOP1은 종료 검증된 진짜 경기 전 관측만 사용합니다. 종목별 80/리그별 60/유사 확률 50개 이상의 선행 결과, 최소 20건 시간순 OOS 검증, Brier 개선 및 90% 보수적 EV +3% 초과를 모두 통과해야 표시됩니다. 기존 공식 frozen TOP1과 별개입니다.
- GitHub 약 10분 스캔은 지연·누락 가능하므로 사전 등록된 경기가 30분 창에서 Betman 목록에서 사라진 경우에도 경고를 기록합니다. 출처가 없는 배당이나 결과를 만들어 복원하지 않습니다.
